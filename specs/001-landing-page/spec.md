# Feature Specification: Landing Page

**Feature Branch**: `001-landing-page`
**Created**: 2026-02-06
**Status**: Draft
**Input**: User description: "Публичная landing page (viably.dev). Hero, How it works, Templates preview, Pricing, Footer. Максимум wow-эффектов."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Понимание продукта через Hero-секцию (Priority: P1)

Новый посетитель заходит на viably.dev впервые и за 5-10 секунд должен понять, что делает продукт, для кого он предназначен и почему стоит попробовать.

**Why this priority**: Это критически важная точка входа - если пользователь не понимает ценность за первые секунды, он покинет сайт. Hero-секция определяет первое впечатление и уровень конверсии.

**Independent Test**: Можно полностью протестировать, показав только Hero-секцию пользователю и спросив: "Что делает этот продукт?" и "Для кого он?". Успех = 90%+ дают правильный ответ.

**Acceptance Scenarios**:

1. **Given** посетитель впервые заходит на главную страницу, **When** он видит Hero-секцию, **Then** он видит главный заголовок, описывающий ценностное предложение, две CTA-кнопки ("Начать бесплатно" и "Смотреть демо"), анимированную демонстрацию процесса создания бота и социальное доказательство (количество созданных ботов)

2. **Given** посетитель находится на Hero-секции, **When** он наводит курсор на страницу, **Then** glow orbs реагируют на позицию мыши, создавая wow-эффект

3. **Given** посетитель смотрит на Hero, **When** проходит 8-10 секунд, **Then** анимированная демо-карточка показывает цикл: typing animation → появление кода → "Bot is live! ✓"

---

### User Story 2 - Понимание процесса через "How It Works" (Priority: P2)

Посетитель хочет понять, как работает создание бота, прежде чем регистрироваться. Он видит три простых шага и понимает, что процесс быстрый и не требует технических знаний.

**Why this priority**: Снижает барьер входа, объясняя простоту процесса. Критично для конверсии, но менее важно чем Hero, так как требует прокрутки страницы.

**Independent Test**: Показать только секцию "How It Works" и попросить пользователя описать процесс создания бота. Успех = пользователь может объяснить 3 шага своими словами.

**Acceptance Scenarios**:

1. **Given** посетитель прокручивает страницу до секции "How It Works", **When** секция появляется в viewport, **Then** три карточки с шагами появляются с staggered fadeInUp анимацией (каждая с задержкой +100ms)

2. **Given** посетитель видит карточку шага, **When** он наводит курсор на карточку, **Then** карточка показывает hover glow эффект

3. **Given** посетитель читает шаги, **When** он видит все три карточки, **Then** он понимает последовательность: "Опиши идею" → "AI генерирует код" → "Деплой одним кликом"

---

### User Story 3 - Выбор шаблона из превью (Priority: P3)

Посетитель хочет посмотреть, какие типы ботов можно создать, и выбрать подходящий шаблон для быстрого старта.

**Why this priority**: Помогает визуализировать конкретные use cases, но не критично для первого понимания продукта. Можно добавить после основных секций.

**Independent Test**: Показать только секцию Templates Preview и попросить пользователя выбрать подходящий шаблон для своей задачи. Успех = пользователь находит релевантный шаблон за <30 секунд.

**Acceptance Scenarios**:

1. **Given** посетитель прокручивает до секции Templates Preview, **When** секция появляется в viewport, **Then** отображается сетка из 6 карточек шаблонов с staggered анимацией появления

2. **Given** посетитель видит карточку шаблона, **When** он наводит курсор на карточку, **Then** карточка показывает hover эффект (поднятие, glow)

3. **Given** посетитель хочет увидеть больше шаблонов, **When** он кликает на ссылку "Смотреть все шаблоны →", **Then** он переходит на страницу галереи шаблонов

---

### User Story 4 - Выбор тарифного плана (Priority: P2)

Посетитель хочет понять стоимость продукта и выбрать подходящий план перед регистрацией.

**Why this priority**: Критично для конверсии платящих пользователей. Прозрачность цен снижает барьер входа и строит доверие.

**Independent Test**: Показать только секцию Pricing и попросить пользователя выбрать план для сценария "10 ботов в месяц". Успех = правильный выбор плана за <1 минуту.

**Acceptance Scenarios**:

1. **Given** посетитель прокручивает до секции Pricing, **When** секция появляется в viewport, **Then** отображаются 3 колонки с планами: Free, Starter, Pro с staggered анимацией

2. **Given** посетитель видит планы, **When** он видит план Pro, **Then** план Pro имеет badge "Popular" и gradient border, выделяясь среди других

3. **Given** посетитель хочет посмотреть годовую оплату, **When** он переключает toggle Monthly/Yearly, **Then** цены обновляются, показывая скидку 20% для годовой подписки

4. **Given** посетитель выбрал план, **When** он кликает на CTA-кнопку плана, **Then** он переходит на страницу регистрации (Free план) или выбора плана (Starter/Pro)

---

### User Story 5 - Навигация и доступ к основным действиям (Priority: P1)

Посетитель хочет в любой момент иметь доступ к навигации, авторизации и регистрации через sticky navigation bar.

**Why this priority**: Критично для UX и конверсии - пользователь должен иметь постоянный доступ к CTA и навигации на всех экранах.

**Independent Test**: Прокрутить страницу до низа и проверить, что nav bar доступен и функционален. Успех = nav виден и все кнопки кликабельны.

**Acceptance Scenarios**:

1. **Given** посетитель находится в верхней части страницы, **When** он видит navigation bar, **Then** nav bar имеет прозрачный фон с меню: Logo | Features Pricing Docs | [Login] [Sign Up →]

2. **Given** посетитель начинает прокручивать страницу вниз, **When** он прокручивает более 100px, **Then** nav bar получает glass effect (blur + opacity transition) и остается sticky

3. **Given** посетитель использует мобильное устройство, **When** он открывает страницу, **Then** nav bar показывает hamburger menu вместо полной навигации

4. **Given** посетитель кликает на кнопку "Sign Up →", **When** клик обработан, **Then** он переходит на страницу регистрации

---

### Edge Cases

- Что происходит, когда пользователь имеет очень медленное интернет-соединение и анимации могут тормозить?
- Как система обрабатывает ситуацию, когда JavaScript отключен в браузере?
- Что происходит, когда пользователь использует очень маленький экран (менее 320px ширины)?
- Как обрабатываются ошибки при загрузке glow orbs анимаций или демо-карточки?
- Что происходит, когда пользователь быстро переключает toggle Monthly/Yearly несколько раз подряд?
- Как система обрабатывает очень длинные заголовки или тексты в шаблонах при локализации?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА отображать Hero-секцию с главным заголовком, подзаголовком, двумя CTA-кнопками, социальным доказательством и анимированной демо-карточкой
- **FR-002**: Система ДОЛЖНА отображать sticky navigation bar с glass effect при прокрутке более 100px
- **FR-003**: Система ДОЛЖНА отображать секцию "How It Works" с тремя карточками шагов, каждая с иконкой, заголовком и описанием
- **FR-004**: Система ДОЛЖНА отображать секцию Templates Preview с сеткой из 6 карточек шаблонов (упрощенная версия: emoji + name + cost)
- **FR-005**: Система ДОЛЖНА отображать секцию Pricing с тремя тарифными планами: Free, Starter, Pro
- **FR-006**: Система ДОЛЖНА отображать Footer с четырьмя колонками навигации, социальными иконками и копирайтом
- **FR-007**: Система ДОЛЖНА поддерживать scroll-triggered анимации для всех секций (fadeInUp on scroll into viewport)
- **FR-008**: Система ДОЛЖНА отображать 3 glow orbs (purple, blue, cyan) в Hero-секции, реагирующих на позицию мыши
- **FR-009**: Система ДОЛЖНА воспроизводить loop-анимацию в демо-карточке каждые 8-10 секунд: typing animation → код появляется → "Bot is live! ✓"
- **FR-010**: Система ДОЛЖНА применять staggered анимации для Template cards и Pricing cards (каждая с задержкой +100ms)
- **FR-011**: Система ДОЛЖНА поддерживать toggle между Monthly/Yearly ценами с автоматическим пересчетом (yearly = скидка 20%)
- **FR-012**: Система ДОЛЖНА отображать badge "Popular" и gradient border для плана Pro
- **FR-013**: Система ДОЛЖНА отображать hamburger menu на мобильных устройствах (responsive design)
- **FR-014**: Все CTA-кнопки "Начать бесплатно" ДОЛЖНЫ вести на страницу /register
- **FR-015**: Все CTA-кнопки "Выбрать план" (Starter/Pro) ДОЛЖНЫ вести на страницу выбора плана
- **FR-016**: Ссылка "Смотреть все шаблоны →" ДОЛЖНА вести на страницу галереи шаблонов
- **FR-017**: Система ДОЛЖНА применять parallax эффект для glow orbs (двигаются медленнее контента при прокрутке)
- **FR-018**: Все секции ДОЛЖНЫ корректно отображаться и стекаться на мобильных устройствах (responsive design)

### Key Entities

- **Landing Page Section**: Логический блок контента (Hero, How It Works, Templates, Pricing, Footer) с собственными анимациями и визуальным стилем
- **Template Card**: Представление шаблона бота с emoji-иконкой, названием и стоимостью в кредитах
- **Pricing Plan**: Тарифный план с названием, ценой, списком возможностей и CTA-кнопкой
- **Navigation Item**: Элемент навигации в header или footer (ссылка на секцию или страницу)
- **Glow Orb**: Анимированный визуальный элемент, создающий wow-эффект и реагирующий на мышь

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Посетители понимают ценностное предложение продукта за первые 10 секунд (90%+ правильных ответов в user testing)
- **SC-002**: Время до первого взаимодействия (клик на CTA) составляет менее 30 секунд для 70%+ новых посетителей
- **SC-003**: Страница полностью загружается и отображает Hero-секцию за менее чем 3 секунды на соединении 3G
- **SC-004**: Все анимации работают плавно (60 FPS) на устройствах средней производительности без jank при прокрутке
- **SC-005**: 80%+ посетителей прокручивают страницу до секции "How It Works" (engagement metric)
- **SC-006**: Конверсия из посещения в клик на CTA составляет не менее 15%
- **SC-007**: Страница корректно отображается на всех популярных разрешениях экрана (320px - 2560px ширина)
- **SC-008**: 95%+ пользователей могут описать процесс создания бота после просмотра секции "How It Works"
- **SC-009**: Время, необходимое для выбора тарифного плана, составляет менее 2 минут для 85%+ пользователей
- **SC-010**: Bounce rate на landing page ниже 40% (industry standard для SaaS landing pages ~50-70%)

## Assumptions

- Предполагается, что пользователи имеют JavaScript включенным в браузере для полноценного опыта с анимациями
- Предполагается использование современных браузеров с поддержкой CSS Grid, Flexbox и CSS animations
- Стандартные web performance метрики: LCP < 2.5s, FID < 100ms, CLS < 0.1
- Социальное доказательство "1,200+ ботов создано" будет обновляться вручную или через API
- Демо-видео в Hero-секции будет предзаписанным, а не live-generated
- Glow orbs будут реализованы через canvas или CSS с оптимизацией производительности
- Pricing toggle сохраняет выбор пользователя в localStorage для персонализации при повторном посещении
- Footer содержит стандартные разделы: Product, Resources, Company, Legal
- Все внешние ссылки (Twitter, GitHub, Telegram) открываются в новой вкладке
- Mobile-first подход: сначала оптимизация для мобильных, затем desktop
- Анимации могут быть отключены для пользователей с prefers-reduced-motion

## Dependencies

- Design System (tokens, animations, glow orbs) - должен быть реализован первым
- Template data - необходимы данные о 6 шаблонах для preview секции
- Pricing data - должны быть определены финальные цены и возможности планов

## Out of Scope

- Полнофункциональная галерея всех шаблонов (будет отдельной страницей)
- Детальные страницы pricing планов (будут отдельными страницами)
- Функциональность "Смотреть демо" (видео плеер или интерактивное демо)
- Интеграция с аналитикой и трекингом (будет добавлено позже)
- A/B тестирование различных вариантов Hero-секции
- Локализация на другие языки (на данном этапе только русский)
- Live chat или support widget
- Cookie consent banner
- Blog или News секция
