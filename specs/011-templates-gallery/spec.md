# Feature Specification: Templates Gallery

**Feature Branch**: `011-templates-gallery`
**Created**: 2026-02-06
**Status**: Draft
**Input**: User description: "Галерея шаблонов ботов с поиском, фильтрами, детальными карточками. Включает Template Detail page."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Просмотр каталога шаблонов (Priority: P1)

Пользователь заходит на страницу "Шаблоны ботов" и видит все доступные шаблоны в виде карточек. Каждая карточка содержит иконку, название, краткое описание, список ключевых возможностей и стоимость в кредитах. Карточки отображаются в адаптивной сетке. Пользователь может быстро оценить предложения и выбрать подходящий шаблон.

**Why this priority**: Это основной экран модуля — без него невозможен доступ к шаблонам. Формирует первое впечатление и обеспечивает навигацию ко всем остальным функциям.

**Independent Test**: Можно протестировать, открыв страницу шаблонов и убедившись, что все 6 шаблонов отображаются корректно с полной информацией на карточках — без поиска, фильтров или детальной страницы.

**Acceptance Scenarios**:

1. **Given** пользователь авторизован, **When** он переходит на страницу шаблонов, **Then** отображается заголовок "Шаблоны ботов", подзаголовок и сетка из 6 карточек шаблонов.
2. **Given** страница шаблонов загружена, **When** пользователь видит карточку, **Then** на ней отображаются: иконка-эмодзи, название, описание (ограничено 2-3 строками), список возможностей (до 4 пунктов), стоимость в кредитах и кнопка действия.
3. **Given** пользователь на десктопе, **When** он наводит курсор на карточку, **Then** карточка приподнимается вверх с плавной анимацией и усилением тени, появляется градиентная линия-разделитель.
4. **Given** пользователь на мобильном устройстве, **When** он просматривает шаблоны, **Then** карточки отображаются в одну колонку с полной шириной экрана.
5. **Given** пользователь на планшете, **When** он просматривает шаблоны, **Then** карточки отображаются в 2 колонки.

---

### User Story 2 - Поиск и фильтрация шаблонов (Priority: P2)

Пользователь хочет быстро найти нужный шаблон. Он вводит текст в строку поиска — карточки фильтруются в реальном времени по названию и описанию. Также доступны фильтры-вкладки для быстрого отбора: все шаблоны, Telegram-боты, популярные, дешёвые (менее 5 кредитов).

**Why this priority**: Поиск и фильтры улучшают UX при масштабировании каталога. При 6 шаблонах пользователь может справиться без них, но для удобства и масштабируемости они необходимы.

**Independent Test**: Можно протестировать, введя поисковый запрос и переключая фильтры — убедиться, что отображаемые карточки соответствуют критериям.

**Acceptance Scenarios**:

1. **Given** страница шаблонов загружена, **When** пользователь вводит "магазин" в поисковую строку, **Then** через 300мс после прекращения ввода отображаются только шаблоны, содержащие "магазин" в названии или описании.
2. **Given** страница шаблонов загружена, **When** пользователь нажимает вкладку "Популярные", **Then** отображаются только шаблоны, помеченные как популярные.
3. **Given** страница шаблонов загружена, **When** пользователь нажимает вкладку "Дешёвые < 5 cr.", **Then** отображаются только шаблоны со стоимостью менее 5 кредитов.
4. **Given** активен фильтр "Telegram" и введён поисковый запрос, **When** ни один шаблон не соответствует обоим критериям, **Then** отображается сообщение "Шаблоны не найдены" с предложением сбросить фильтры.
5. **Given** пользователь применил фильтр, **When** он нажимает вкладку "Все", **Then** фильтр сбрасывается и отображаются все шаблоны.

---

### User Story 3 - Просмотр детальной информации о шаблоне (Priority: P2)

Пользователь кликает на карточку шаблона и переходит на детальную страницу. Здесь он видит полное описание бота, список всех возможностей, перечень настраиваемых полей (что нужно заполнить при создании проекта) и стоимость в кредитах. Страница помогает принять информированное решение о создании проекта.

**Why this priority**: Детальная страница — обязательный шаг между просмотром каталога и созданием проекта. Без неё пользователь не получит полной информации для принятия решения.

**Independent Test**: Можно протестировать, перейдя на детальную страницу любого шаблона и проверив отображение всей информации, навигацию назад и адаптивность.

**Acceptance Scenarios**:

1. **Given** пользователь на странице галереи, **When** он кликает на карточку шаблона или кнопку "Использовать", **Then** он переходит на детальную страницу этого шаблона.
2. **Given** пользователь на детальной странице, **When** страница загружена, **Then** отображаются: иконка, название, описание, градиентный разделитель, стоимость в кредитах, список возможностей и перечень настраиваемых полей.
3. **Given** пользователь на детальной странице, **When** он нажимает "Назад к шаблонам", **Then** он возвращается на страницу галереи.
4. **Given** пользователь на мобильном устройстве, **When** он просматривает детальную страницу, **Then** двухколоночный макет перестраивается в одноколоночный (информация сверху, детали снизу).

---

### User Story 4 - Создание проекта из шаблона (Priority: P3)

Пользователь, изучив шаблон на детальной странице, нажимает кнопку "Создать проект". Система проверяет достаточность кредитов. При наличии кредитов — создаётся проект и пользователь перенаправляется на страницу генерации. При нехватке — кнопка неактивна, отображается подсказка "Недостаточно кредитов" и ссылка на пополнение.

**Why this priority**: Функция создания проекта зависит от интеграции с модулями проектов и кредитов. Для MVP достаточно визуального отображения кнопки и проверки кредитов — фактическое создание проекта может быть заглушкой.

**Independent Test**: Можно протестировать, нажав кнопку "Создать проект" при достаточном и недостаточном балансе кредитов — убедиться в корректном поведении в обоих случаях.

**Acceptance Scenarios**:

1. **Given** пользователь на детальной странице шаблона и у него достаточно кредитов, **When** он нажимает "Создать проект", **Then** создаётся новый проект и пользователь перенаправляется на страницу генерации.
2. **Given** пользователь на детальной странице шаблона и у него недостаточно кредитов, **When** он видит кнопку "Создать проект", **Then** кнопка неактивна (disabled), отображается подсказка "Недостаточно кредитов" и ссылка "Пополнить".
3. **Given** пользователь нажал "Создать проект", **When** процесс создания выполняется, **Then** отображается индикатор загрузки на кнопке, повторное нажатие заблокировано.

---

### Edge Cases

- Что происходит, если пользователь переходит по прямой ссылке на несуществующий шаблон (`/templates/invalid-slug`)? — Отображается страница "Шаблон не найден" с навигацией назад к галерее.
- Что происходит, если все шаблоны отфильтрованы (пустой результат)? — Отображается пустое состояние с сообщением и кнопкой сброса фильтров.
- Что происходит при очень длинном названии или описании шаблона? — Текст обрезается с многоточием (line-clamp).
- Что происходит, если пользователь быстро переключает фильтры? — Debounce на поиске (300мс), мгновенное переключение фильтров без гонки состояний.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА отображать страницу галереи шаблонов со списком всех доступных шаблонов в виде карточек.
- **FR-002**: Каждая карточка шаблона ДОЛЖНА содержать: иконку (эмодзи), название, описание (ограниченное 2-3 строками), список возможностей (до 4 пунктов), стоимость в кредитах и кнопку действия.
- **FR-003**: Система ДОЛЖНА предоставлять строку поиска с отложенным поиском (debounce 300мс), фильтрующую шаблоны по названию и описанию в реальном времени на стороне клиента.
- **FR-004**: Система ДОЛЖНА предоставлять фильтры-вкладки в стиле "pill": Все, Telegram, Популярные, Дешёвые (< 5 кредитов). Поиск и фильтры ДОЛЖНЫ работать совместно.
- **FR-005**: Сетка карточек ДОЛЖНА быть адаптивной: 3 колонки на десктопе, 2 на планшете, 1 на мобильном устройстве.
- **FR-006**: Карточки ДОЛЖНЫ иметь анимацию при наведении: подъём вверх, усиление тени, появление градиентной линии-разделителя, плавный переход рамки.
- **FR-007**: Клик на карточку ДОЛЖЕН переводить пользователя на детальную страницу шаблона.
- **FR-008**: Детальная страница ДОЛЖНА отображать полную информацию о шаблоне: иконку, название, описание, стоимость, список возможностей и перечень настраиваемых полей.
- **FR-009**: Детальная страница ДОЛЖНА иметь двухколоночный макет (40%/60%) на десктопе с перестройкой в одну колонку на мобильных устройствах.
- **FR-010**: Детальная страница ДОЛЖНА содержать навигацию "Назад к шаблонам" для возврата в галерею.
- **FR-011**: Кнопка "Создать проект" на детальной странице ДОЛЖНА проверять достаточность кредитов у пользователя.
- **FR-012**: При недостаточном балансе кредитов кнопка создания проекта ДОЛЖНА быть неактивной с подсказкой "Недостаточно кредитов" и ссылкой на пополнение.
- **FR-013**: При достаточном балансе и нажатии кнопки "Создать проект" система ДОЛЖНА создать проект и перенаправить пользователя на страницу генерации.
- **FR-014**: Система ДОЛЖНА отображать пустое состояние с сообщением и предложением сбросить фильтры, когда ни один шаблон не соответствует критериям поиска/фильтрации.
- **FR-015**: Система ДОЛЖНА отображать страницу "Шаблон не найден" при переходе по прямой ссылке на несуществующий slug.
- **FR-016**: Система ДОЛЖНА содержать 6 предустановленных шаблонов ботов с определёнными категориями, стоимостями и списками возможностей.

### Key Entities

- **Template (Шаблон)**: Предустановленный шаблон бота. Атрибуты: уникальный идентификатор (slug), название, иконка (эмодзи), описание, категория, стоимость в кредитах, список возможностей, теги, настраиваемые поля, признак популярности.
- **ConfigField (Настраиваемое поле)**: Описание поля, которое пользователь заполняет при создании проекта из шаблона. Атрибуты: имя, метка, тип ввода (текст, текстовое поле, выбор, множественный выбор, число), обязательность, подсказка, варианты выбора.
- **Filter State (Состояние фильтрации)**: Текущее состояние поиска и активного фильтра. Атрибуты: поисковый запрос, активная вкладка фильтра.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может найти нужный шаблон (из 6 доступных) менее чем за 15 секунд с использованием поиска или фильтров.
- **SC-002**: Все 6 карточек шаблонов загружаются и отображаются корректно при первом посещении страницы.
- **SC-003**: Пользователь может перейти от галереи к детальной странице шаблона и обратно за 1 клик в каждом направлении.
- **SC-004**: Все интерактивные элементы (карточки, фильтры, поиск, кнопки) отзывчивы — визуальный отклик при взаимодействии происходит мгновенно (менее 100мс).
- **SC-005**: Галерея корректно отображается на экранах от 320px до 2560px ширины без горизонтальной прокрутки и обрезки контента.
- **SC-006**: 100% пользователей с достаточным балансом кредитов могут успешно инициировать создание проекта из шаблона.
- **SC-007**: Пользователь с недостаточным балансом кредитов однозначно видит причину невозможности создания проекта и путь к пополнению.

## Assumptions

- MVP использует клиентскую фильтрацию (client-side), так как каталог содержит только 6 шаблонов.
- Данные шаблонов хранятся как mock-данные на клиенте. Интеграция с бэкенд API (модуль 004-templates) будет реализована в отдельном модуле.
- Проверка баланса кредитов для MVP использует mock-данные из zustand store.
- Создание проекта в MVP может быть заглушкой (mock) с редиректом на placeholder-страницу.
- Все 6 шаблонов относятся к категории "telegram_bot" — фильтр "Telegram" показывает все шаблоны.
- Навигация интегрирована с существующим layout-компонентом (sidebar + navbar).
