# PRD: Production-Quality Preview System

**Status:** Draft
**Feature:** Замена Babel+stubs превью на production-grade систему
**Приоритет:** Critical

---

## 1. Problem Statement

### Текущая ситуация

Когда пользователь генерирует фронтенд-проект (лендинг, веб-приложение, UI-компонент), Viably показывает превью через самодельный механизм:

- Весь код сливается в один файл, imports вырезаются regex-парсером
- Babel standalone транспилирует JSX прямо в браузере
- Компоненты shadcn/ui, React Router, TanStack Query заменяются самодельными «заглушками» (stubs)
- Результат рендерится в `<iframe>` с injected HTML

### Проблемы

**Нестабильность:**
- Частые runtime-ошибки: компоненты падают из-за неполных заглушек
- Переименованные экспорты, `displayName`, Radix UI паттерны — всё это ломается
- Дедупликация компонентов по имени — хрупкая эвристика, регулярно даёт сбои
- CSS `@apply`, `:root`-блоки, `@layer` — требуют сложной обработки с бесконечными edge-cases

**Недоступность на Apple-устройствах:**
- На iPhone и MacBook превью не открывается совсем (ошибка при загрузке)
- Связано с ограничениями Safari на inline script execution и cross-origin политиками
- Блокирует значительную часть целевой аудитории

**Низкое качество UX:**
- Пользователь видит «сломанное» превью и не понимает, что реальный код рабочий
- Анимации, интерактивность, hover-эффекты часто не работают
- Реальные npm-зависимости не поддерживаются

**Репутационный ущерб:**
- Конкуренты (Lovable, bolt.new, v0.dev) показывают работающие превью — пользователь сравнивает
- «Превью сломано» = «продукт не работает» в восприятии пользователя

## 3. Feature Scope

### In Scope

1. **Замена текущего механизма превью** на WebContainers-based или Sandpack-based подход
2. **Полная поддержка React + Tailwind CSS + shadcn/ui** без заглушек
3. **Интерактивное превью** — клики, скролл, формы, анимации работают как в реальном браузере
4. **Превью работает на всех устройствах и браузерах**, включая Safari на iPhone и MacBook
5. **Device preview**: переключение desktop/tablet/mobile (уже есть в UI, должно работать корректно)
6. **Обновление превью после регенерации** — когда AI обновляет код, превью обновляется
7. **Состояния загрузки** — понятный индикатор пока превью собирается

### Out of Scope

- Редактирование кода прямо в превью (visual edit, как у Lovable)
- Поддержка SSR/API routes в превью
- Превью Telegram-бота (это отдельная задача)
- Публичная ссылка на превью для шаринга
- Превью в реальном времени (hot reload во время генерации)

## 4. Solution Overview

### Выбранный подход: WebContainers (`@webcontainer/api`)

На основе анализа конкурентов — наилучшее соотношение качества и стоимости для нашего use case:

| Критерий | WebContainers | Sandpack | Cloud VM (Lovable) |
|---|---|---|---|
| Реальный npm | Да (WASM Node.js) | Ограничен (CDN) | Да (настоящий Node.js) |
| Tailwind v4 | Да | Нет (v3 template) | Да |
| Safari/iPhone | Да | Да | Да |
| Инфраструктурные расходы | Нет | Нет | Высокие |
| Время внедрения | Среднее | Быстрое | Долгое |
| Зависимость от внешних сервисов | StackBlitz CDN | CodeSandbox CDN | Fly.io |

**Альтернатива (fallback): Sandpack** — если WebContainers окажется несовместим с нашими CSP/header требованиями (требует `COOP: same-origin` + `COEP: require-corp`).

### Как это работает

1. При открытии превью — WebContainers boot в браузере (~1-2 сек)
2. Файлы проекта записываются в виртуальную FS
3. `npm install` запускается в WASM Node.js (быстро — пакеты кешируются)
4. `vite dev` запускается, выдаёт localhost URL внутри WebContainer
5. Этот URL открывается в `<iframe>` — полноценный браузер
6. При изменении кода — Vite HMR обновляет превью мгновенно

## 5. User Experience Requirements

### UX-1: Loading States
- При первом запуске превью показывается прогресс-индикатор с этапами: «Загрузка окружения» → «Установка зависимостей» → «Запуск сервера»
- Загрузка не блокирует просмотр кода — редактор доступен

### UX-2: Error Handling
- Если сборка падает — показывается понятная ошибка с возможностью перезапустить
- Ошибка не должна выглядеть как «наш продукт сломан» — скорее «в коде есть проблема»

### UX-3: Device Preview
- Переключатель desktop/tablet/mobile работает через изменение ширины iframe
- Mobile-превью (375px) должен корректно отображать адаптивный дизайн

### UX-4: Refresh
- Кнопка «Обновить превью» для ручного перезапуска
- После регенерации кода AI — автоматическое обновление превью

### UX-5: Safari Compatibility
- Превью полностью работает в Safari (iPhone, MacBook)
- Никаких пустых экранов или ошибок консоли на Apple-устройствах

## 6. Technical Considerations (High-Level)

### Заголовки безопасности
WebContainers требует:
```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```
Эти заголовки могут конфликтовать с внешними скриптами (аналитика, чат-виджеты). Необходимо проверить совместимость с текущим стеком или использовать `credentialless` вариант COEP.

### Структура файлов проекта
Текущий AI генерирует набор artifacts (файлы). Новый превью-механизм должен получать файлы в виде дерева `{ path: content }` и записывать их в WebContainer FS.

### Производительность
- `npm install` при первом запуске может занять 10-30 сек без кеша
- С кешем (последующие запуски) — 1-5 сек
- Необходимо показывать прогресс, чтобы пользователь не думал, что всё зависло

### Изоляция
- Каждая вкладка/сессия получает свой WebContainer инстанс
- Код пользователя изолирован в WASM sandbox — нет доступа к filesystem хоста

## 9. Risks & Mitigation

| Риск | Вероятность | Митигация |
|---|---|---|
| WebContainers несовместим с текущими CSP | Средняя | Fallback на Sandpack |
| Safari не поддерживает SharedArrayBuffer | Низкая | Safari 15.4+ поддерживает |
| Медленный первый запуск (>30 сек) | Средняя | Показывать прогресс; кешировать npm |
| StackBlitz изменяет условия использования | Низкая | Self-host bundler как fallback |
| AI генерирует код с ошибками — виним превью | Высокая | Чёткий UI различения «ошибка кода» vs «ошибка превью» |
