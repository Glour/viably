# Feature Specification: AI Code Generation Module

**Feature Branch**: `006-ai-generation`
**Created**: 2026-02-05
**Status**: Draft
**Input**: User description: "AI code generation module with Claude Sonnet 4 for generating Telegram bot code from templates"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Generate Code for Project (Priority: P1)

Пользователь создал проект на основе шаблона и заполнил конфигурацию. Теперь он хочет сгенерировать готовый код Telegram-бота. Пользователь нажимает кнопку "Сгенерировать код", система списывает кредиты, запускает генерацию через Claude Sonnet 4 и после завершения показывает результат.

**Why this priority**: Это основная ценность модуля - без генерации кода весь модуль бесполезен. Пользователь платит за эту функцию.

**Independent Test**: Можно полностью протестировать создав проект с шаблоном, запустив генерацию и проверив, что код сохранён в проекте.

**Acceptance Scenarios**:

1. **Given** проект в статусе "draft" с заполненной конфигурацией и достаточным балансом кредитов, **When** пользователь запрашивает генерацию, **Then** статус меняется на "generating", кредиты списываются, и после завершения статус становится "ready" с сгенерированным кодом
2. **Given** проект в статусе "draft", **When** баланс кредитов недостаточен, **Then** система отклоняет запрос с понятным сообщением об ошибке
3. **Given** проект в статусе "generating", **When** пользователь запрашивает повторную генерацию, **Then** система отклоняет запрос, так как генерация уже выполняется

---

### User Story 2 - View Generation Result (Priority: P1)

После успешной генерации пользователь хочет просмотреть сгенерированный код - список файлов и их содержимое.

**Why this priority**: Без возможности просмотра результата генерация теряет смысл. Пользователь должен видеть, что он получил за свои кредиты.

**Independent Test**: Можно протестировать взяв проект со статусом "ready" и проверив, что все сгенерированные файлы доступны для просмотра.

**Acceptance Scenarios**:

1. **Given** проект в статусе "ready" с сгенерированным кодом, **When** пользователь запрашивает результат, **Then** система возвращает список файлов с их содержимым
2. **Given** проект в статусе "draft" или "generating", **When** пользователь запрашивает результат, **Then** система возвращает ошибку о том, что код ещё не сгенерирован

---

### User Story 3 - Handle Generation Errors with Credit Refund (Priority: P1)

Если во время генерации произошла ошибка (проблема с API, некорректный ответ), пользователь должен получить возврат кредитов и понятное сообщение об ошибке.

**Why this priority**: Критически важно для доверия пользователей - они не должны терять деньги при сбоях системы.

**Independent Test**: Можно протестировать симулируя ошибку API и проверяя, что кредиты возвращены и статус проекта корректный.

**Acceptance Scenarios**:

1. **Given** проект с запущенной генерацией, **When** происходит ошибка API, **Then** кредиты возвращаются пользователю, статус проекта становится "error" с описанием ошибки
2. **Given** проект в статусе "error", **When** пользователь запрашивает повторную генерацию, **Then** система позволяет запустить генерацию заново (с повторным списанием кредитов)

---

### User Story 4 - Asynchronous Generation Processing (Priority: P2)

Генерация кода занимает время (30-120 секунд). Пользователь запускает генерацию и может заниматься другими делами, пока система обрабатывает запрос в фоновом режиме.

**Why this priority**: Улучшает UX - пользователь не должен ждать на заблокированной странице. Однако синхронная генерация тоже работоспособна для MVP.

**Independent Test**: Можно протестировать запустив генерацию, проверив что ответ приходит сразу с task_id, и затем отслеживая статус до завершения.

**Acceptance Scenarios**:

1. **Given** валидный запрос на генерацию, **When** пользователь отправляет запрос, **Then** система немедленно возвращает подтверждение с идентификатором задачи
2. **Given** запущенная задача генерации, **When** пользователь запрашивает статус, **Then** система возвращает текущий прогресс (pending, processing, completed, failed)

---

### User Story 5 - Retry Failed Generation (Priority: P2)

При временных сбоях (таймауты, rate limits) система должна автоматически повторить попытку генерации.

**Why this priority**: Повышает надёжность системы без вмешательства пользователя. Однако ручной повтор тоже приемлем для MVP.

**Independent Test**: Можно протестировать симулируя временный сбой и проверяя, что система делает повторную попытку.

**Acceptance Scenarios**:

1. **Given** временная ошибка при генерации (таймаут, rate limit), **When** первая попытка не удалась, **Then** система автоматически повторяет попытку (до 3 раз)
2. **Given** все попытки исчерпаны, **When** последняя попытка не удалась, **Then** система возвращает кредиты и устанавливает статус "error"

---

### User Story 6 - Admin Monitoring (Priority: P3)

Администратор хочет видеть статус AI-сервиса для мониторинга работоспособности.

**Why this priority**: Полезно для поддержки, но не критично для основной функциональности.

**Independent Test**: Можно протестировать вызовом эндпоинта статуса от имени администратора.

**Acceptance Scenarios**:

1. **Given** администратор авторизован, **When** запрашивает статус AI-сервиса, **Then** получает информацию о работоспособности и используемой модели
2. **Given** обычный пользователь, **When** запрашивает статус AI-сервиса, **Then** получает ошибку доступа

---

### Edge Cases

- Что происходит, когда AI возвращает ответ без валидных блоков кода?
- Как система обрабатывает очень длинные ответы, превышающие лимит токенов?
- Что происходит при параллельных запросах генерации для одного проекта?
- Как обрабатывается ситуация, когда шаблон проекта был удалён после создания проекта?
- Что происходит, если баланс кредитов изменился между проверкой и списанием?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST позволять запускать генерацию кода для проекта в статусе "draft"
- **FR-002**: Система MUST списывать кредиты перед началом генерации
- **FR-003**: Система MUST возвращать кредиты при ошибке генерации
- **FR-004**: Система MUST строить промпт из шаблона и пользовательской конфигурации
- **FR-005**: Система MUST извлекать файлы кода из ответа AI
- **FR-006**: Система MUST сохранять сгенерированный код в проекте
- **FR-007**: Система MUST обновлять статус проекта на каждом этапе (draft → generating → ready/error)
- **FR-008**: Система MUST логировать все этапы генерации для отладки
- **FR-009**: Система MUST поддерживать асинхронную обработку генерации
- **FR-010**: Система MUST автоматически повторять попытки при временных сбоях (до 3 раз)
- **FR-011**: Система MUST предоставлять эндпоинт статуса AI-сервиса для администраторов
- **FR-012**: Система MUST отклонять запросы генерации при недостаточном балансе кредитов
- **FR-013**: Система MUST отклонять повторные запросы генерации для проекта в статусе "generating"
- **FR-014**: Система MUST возвращать понятные сообщения об ошибках пользователю

### Key Entities

- **Generation Task**: Представляет задачу генерации кода - связана с проектом, содержит статус, логи и результат
- **Generated Code**: Результат генерации - набор файлов с именами и содержимым, хранится в проекте
- **Prompt**: Построенный запрос к AI - комбинация системного промпта, шаблона и пользовательской конфигурации

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может получить сгенерированный код за время не более 3 минут с момента запроса
- **SC-002**: 95% успешных генераций содержат все необходимые файлы для работающего бота
- **SC-003**: При ошибках генерации 100% кредитов возвращаются пользователю в течение 1 минуты
- **SC-004**: Система выдерживает 100 одновременных запросов на генерацию без деградации
- **SC-005**: Автоматические повторы снижают количество финальных ошибок на 80% по сравнению с одиночными попытками
- **SC-006**: 90% пользователей успешно генерируют код с первой попытки (без ручного повтора)

## Assumptions

- Стоимость одной генерации составляет 10 кредитов (фиксированная стоимость)
- Используется модель Claude Sonnet 4 (claude-sonnet-4-20250514)
- Максимальное количество токенов в ответе: 8192
- Формат файлов в ответе AI: markdown code blocks с комментарием `# filename: path/to/file.py`
- Временные файлы и результаты хранятся в JSON-структуре в поле `generated_code` проекта
- Система использует Celery + Redis для асинхронной обработки задач

## Out of Scope

- Ревью сгенерированного кода на безопасность (отложено для будущих версий)
- Тестирование кода в sandbox-окружении
- Streaming генерации (показ результата по мере генерации)
- Кастомизация модели AI пользователем
- Ручное редактирование промптов пользователем
