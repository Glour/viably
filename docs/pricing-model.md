**Версия:** 2.0
**Обновлено:** 27 февраля 2026
**Статус:** Реализовано (коммит `cb3fcbc`)

---

## 1. Обзор

Viably использует **кредитную систему с динамическим ценообразованием**. Стоимость каждого AI-запроса рассчитывается на основе фактически потреблённых токенов — чем сложнее запрос, тем больше кредитов он стоит. Это заменяет прежнюю фиксированную модель (1 кредит = 1 сообщение).

### Ключевые принципы

- **Post-pay**: кредиты списываются ПОСЛЕ генерации, по факту потребления
- **Прозрачность**: пользователь видит, сколько кредитов списалось за каждое сообщение
- **Smart routing**: простые вопросы идут на дешёвую модель (Haiku), сложные — на мощную (Sonnet)
- **Проекты безлимитны**, ограничиваются только **деплои** (= Docker-контейнеры на VPS)

## 3. Динамическое ценообразование кредитов

### 3.1 Формула

```
credits = max(1, min(100, ceil((input_tokens + output_tokens × 3) / 10 000)))
```

- **Input tokens** — токены запроса (системный промпт + история + сообщение)
- **Output tokens** — токены ответа AI (взвешены ×3, т.к. Anthropic берёт за output ~5x дороже)
- **Минимум**: 1 кредит (safety floor)
- **Максимум**: 100 кредитов (safety cap)
- **Делитель**: 10 000 (1 кредит ≈ 10K weighted tokens)

### 3.2 Примеры стоимости

| Сценарий | Input | Output | Weighted | Кредиты |
|---|---|---|---|---|
| Простой вопрос (Haiku) | 5K | 200 | 5 600 | **1** |
| Вопрос средней сложности | 15K | 500 | 16 500 | **2** |
| Правка стилей/текста | 18K | 2K | 24 000 | **3** |
| Генерация компонента | 35K | 8K | 59 000 | **6** |
| Сложная генерация (5 итераций) | 80K | 30K | 170 000 | **17** |
| Агентный цикл (20 итераций) | 200K | 80K | 440 000 | **44** |
| Экстремальный цикл (50 итераций) | 400K | 150K | 850 000 | **85** |
| Максимум (cap) | 1M+ | 500K+ | 2 500 000+ | **100** |

### 3.3 Post-pay биллинг

Схема списания:

1. **До генерации**: проверяем, что `credits >= 1` (MIN_CREDIT_COST). Не списываем, только проверяем
2. **Генерация**: AI обрабатывает запрос, стримит ответ
3. **После генерации**: получаем реальный usage (input_tokens, output_tokens) от Anthropic API
4. **Расчёт**: вычисляем `calculate_dynamic_cost(input_tokens, output_tokens)`
5. **Списание**: атомарно списываем кредиты (SELECT FOR UPDATE)
6. **Уведомление**: отправляем клиенту WS event `credits_used` с суммой и остатком
7. **При ошибке генерации**: кредиты НЕ списываются

Данные о потреблении токенов сохраняются в `credit_transactions.token_metadata` (JSONB):
```json
{
  "input_tokens": 15000,
  "output_tokens": 500,
  "cache_read_tokens": 12000,
  "cache_creation_tokens": 0,
  "model": "haiku"
}
```

## 4. Smart Routing (умная маршрутизация)

### 4.1 Классификатор запросов

Каждый входящий запрос классифицируется без вызова LLM (keyword + heuristics):

| Уровень | Критерии | Модель | Промпт |
|---|---|---|---|
| **SIMPLE** | Вопросы ("что", "как", "почему", "explain"), < 300 символов, без кодовых слов | Claude Haiku 4.5 | Только BASE_PROMPT (~10KB) |
| **STANDARD** | Всё, что не SIMPLE и не FULL | Claude Sonnet 4.6 | BASE_PROMPT + категория |
| **FULL** | Содержит триггеры ("создай", "добавь", "измени", "create", "build", "fix"), или has_artifacts + длинное сообщение | Claude Sonnet 4.6 | BASE_PROMPT + категория + template + boilerplate (~43KB) |

### 4.2 Стоимость моделей (Anthropic API)

| Модель | Input | Output | Cache read |
|---|---|---|---|
| Claude Sonnet 4.6 | $3.00 / 1M | $15.00 / 1M | $0.30 / 1M |
| Claude Haiku 4.5 | $0.80 / 1M | $4.00 / 1M | $0.08 / 1M |

Haiku дешевле Sonnet в **3.75x** по обоим направлениям.

### 4.3 Тиерная система промптов

| Уровень | Что включено | Размер | Экономия |
|---|---|---|---|
| SIMPLE | BASE_PROMPT | ~10KB | **-75%** токенов vs FULL |
| STANDARD | BASE_PROMPT + CATEGORY_PROMPT | ~25KB | **-40%** vs FULL |
| FULL | BASE + CATEGORY + TEMPLATE + BOILERPLATE | ~43KB | 0% (максимум) |

### 4.4 Prompt Caching

Системный промпт разбит на блоки с разным режимом кеширования:

```python
system_blocks = [
    {"type": "text", "text": base_prompt, "cache_control": {"type": "ephemeral"}},       # Статика — кешируется
    {"type": "text", "text": category_prompt, "cache_control": {"type": "ephemeral"}},    # Полустатика — кешируется
    {"type": "text", "text": template_and_boilerplate},                                    # Динамика — не кешируется
]
```

При повторных запросах в рамках одной сессии (5 мин TTL) кешированные блоки читаются по цене **$0.30/1M** вместо **$3.00/1M** (экономия 90% на input).

## 5. Лимиты деплоев

### 5.1 Зачем

Каждый деплой — это Docker-контейнер (0.25 vCPU, 256 MB RAM) на VPS. Сервер вмещает ~20-30 контейнеров. Ограничение деплоев защищает инфраструктуру.

### 5.2 Лимиты по планам

| План | Макс деплоев | Проекты |
|---|---|---|
| Free | 0 | Безлимит |
| Starter | 2 | Безлимит |
| Pro | 5 | Безлимит |
| Business | 15 | Безлимит |
| Enterprise | Без лимита | Безлимит |

При попытке деплоя сверх лимита возвращается ошибка с предложением апгрейда плана.

### 5.3 Стоимость инфраструктуры

Серверы на Hetzner Cloud:

| Сервер | План | Стоимость |
|---|---|---|
| Dev VPS | CX32 (4 vCPU, 8 GB) | ~$6/мес |
| Prod VPS | CX42 (8 vCPU, 16 GB) | ~$10/мес |
| **Итого** | | **~$16/мес** |

Средняя стоимость одного контейнера: **~$0.30-0.50/мес** (при 20-50 контейнерах).

## 6. UX: Отображение кредитов

### 6.1 В чате

После каждого AI-ответа клиент получает WebSocket event:
```json
{"type": "credits_used", "amount": 6, "remaining": 94}
```

### 6.2 Предупреждение о низком балансе

При `remaining < 10` кредитов показывается toast:
- "Осталось мало кредитов"
- Описание: "Осталось N кредитов. Пополните баланс."
- Кнопка "Купить" → страница подписки

### 6.3 Что НЕ списывает кредиты

- Просмотр существующего кода
- Скачивание кода
- Ре-деплой (без изменений)
- Просмотр шаблонов
- Ошибки генерации
